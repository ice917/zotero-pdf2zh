# 中继器(relay)规格 —— 表格翻译管线缺失的一环

状态: **本地侧已实施**(watch_clip.py, 见 §8); 远端侧仍冻结待触发 | 定稿: 2026-09-21
依据: 端到端演练已通(mock) + 真实往返已通(豆包网页版, 见 check_report.txt)

## 1. 定位

```
mk_grid.py(切格) → mk_job.py(装配) → 【中继: 本件】 → check_job.py(对账回填)
```
两端已实测跑通; 中继是唯一缺失件, 故意做薄(目标 ≤150 行)。

## 2. 接口契约(冻结)

- 输入: `job_doubao.txt`(编号<TAB>文本, ≤2k 字符/表, 一次粘贴量)
- 输出: `job_response.tsv`(编号<TAB>译文, 原样落盘, 后续由 check_job.py 验)
- 内部统一走 **OpenAI Chat Completions 格式**(messages = preamble + job 文本)
- **后端 = 可替换件**, 四选一, 接口不变:
  1. 人工粘贴(现状, 0 成本, 每表 2 次粘贴)
  2. 官方 API(最稳, 付费)
  3. 本地模型 Ollama(免费+全私有; 任务已剥到只剩自由文本短语, 小模型可能够用)
  4. 网页逆向网关(免费, 见 §5, ToS 灰色)

## 3. 触发条件(何时才造)

- 一本书 >5 张表, 或多本书批量化 —— 未触发前人工中继是最优解
- 豆包连接器/任务功能收费化 → 退回普通对话框, 管线不受影响(实测未依赖连接器)

## 4. 权限边界(红线, 写死)

1. 只读白名单目录(如 `logs\table_appendix\`), 无全盘权限
2. 无上传权 —— 只取 job 文本, 本地文件本体(PDF/manifest)永不离开
3. 只写 `job_response.tsv` 一个文件
4. 凭据(sessionid/API key)存本地配置, 不进 git
5. **校验权不外放** —— 对账永远本地跑, 被翻译方不得自校(G1-G5 门禁)

## 5. 调研结论(2026-09-21, 网搜)

**网页 AI 转 API(豆包无官方免费接口的替代):**
- `doubao2api` (github.com/wangchuxiaoji-oss/doubao2api): Playwright+Chromium **BrowserOnly** 架构, 浏览器内 fetch 由字节 JS 自动注入 a_bogus/msToken 签名("不逆向签名, 逆向浏览器环境"), 暴露 OpenAI 兼容 `/v1/chat/completions`; 扫码登录一次, 会话持久化; 不需会员
- `LLM-Red-Team/doubao-free-api` / `1994qrq/2025doubao-free-api`: sessionid cookie 逆向代理, OpenAI 格式互译(较老, 纯协议伪造, 有风控风险)
- ⚠ 风险: 逆向 = 服务条款灰色; 账号有风控/封禁可能; 后者 README 被自动扫描标出 secret-exfiltration 提示, **采用前必须通读源码**

**Zotero 生态(网页 AI 接入先例, 证明模式成立):**
- `zotero-pdf-translate`(windingwind, 11.8k★): 翻译服务里有 **Custom GPT** = 任意 OpenAI 兼容端点 → 本地跑 doubao2api 后 Zotero 可直接把它当翻译服务
- `llm-for-zotero`(yilewang): 支持 **WebChat 模式**(不用 API key, 驱动网页版 ChatGPT/DeepSeek) —— "驱动网页 AI"已有实现先例
- Zotero AI Bar: 插件列表直接支持 Doubao

**通用:**
- `browser-use`: 通用浏览器自动化框架, 可作中继的驱动层(比逐站写 userscript 稳)

## 6. 决策建议

1. **只自动化本地侧**(已实施, §8); 远端侧保持手工, 触发条件未到不造
2. 造时只造中继层, 两端不动
3. 后端优先序: 官方 API > 本地模型 > 逆向网关(仅前两者不可用且用户知情时)

### 6.1 为何"只自动化本地侧"(2026-09-21 修订)

原判断"现在不造"针对的是**浏览器自动化**。修订后的分界更精确:

- **浏览器自动化越深越脆弱** —— 豆包改一次 DOM, 插件即废
- **手工复制粘贴这条路换任何 AI、任何版本都不会坏**, 且天然兼容免费版(无连接器/工作任务)
- 而"回复 → 文件 → 对账 → 出稿"这段 **100% 在本地**, 完全可控

故: AI 侧 = 一次粘贴 + 一次复制(手工); 本地侧 = 全自动。这样既拿到零操作体验,
又不引入任何远端脆弱性。

## 7. 隐私不变量(任何后端不变)

走出本机的只有 job 文本: 无表格结构、无学名/命名人/引文(禁翻列未发出)、数字全为 {S###} 占位符、无文件路径。保真不靠翻译方自觉, 靠 check_job.py 门禁。

## 8. 已实施件: watch_clip.py(本地侧中继)

```
mk_job.py(装配) → [豆包网页版 · 普通对话框 · 手工粘贴] → watch_clip.py → check_job.py → mk_appendix.py
                                                          ↑ 用户唯一动作: 在回复上点「复制」
```

把"存成文件 + 跑脚本"两步合并成一次 Ctrl+C。零依赖(剪贴板走 ctypes 调 Win32 API,
不需 pyperclip); 支持两类任务(表格正文 k 编号 / 表注 n 编号), 自动判别走哪个对账器。

**三重识别(防误触发, 全部实测)**

| 判据 | 作用 |
|---|---|
| 单元编号齐全(115 个 k / 3 个 n) | 日常复制凑不齐这么多连续编号 |
| 不含装配前缀 `【待译】`/`【任务】` | **防把发出去的 job 文本当回包**(它编号同样齐全) |
| 至少一个单元含中日韩字符 | 防把英文原文当译文。**门槛不能是"过半"** —— 规则 6 要求文献条目整条保持英文, 文献重区段的中文单元到不了半(v32 切分后 p8–p9 实测 28/65=43%, 合规回包被"过半"整段误拒, 2026-09-25) |

**实测记录(2026-09-21)**

- 表格回包(把真实回包 TAB→空格模拟网页渲染): 识别 115 单元 → G1-G5 全过 → 出稿。
  落盘内容与原始回包**逐条一致、顺序一致、零值差异**(哈希差异仅行尾空白)
- 表注回包: 识别 3 单元 → G1/G2/G3/G5/G6 全过 → notes_zh.json → 出稿
- 防误触发: 剪贴板放入 job_doubao.txt 全文 → **无任何识别输出**, 正确忽略

**实测记录(2026-09-25, v32 文献条目切分之后)**

- 同一区段 p8–p9 的单元数 31 → 65, 其中规则 6 要求保持英文的文献条目 37 条 ——
  中文单元上限 28/65 = 43%
- **旧判据"过半"整段误拒合规回包**: 报错 `没有识别到完整回包(编号不齐)`, 而诊断行
  自相矛盾地打印 `「正文 v32_refs_p8p9」期望 65 条 / 读到 65 条`(编号其实是齐的)
- 对照: 违反规则 6(把文献也译成中文)反而过得了前端, 但被门禁判死
  `FAIL #S15 高价值字形未回锚: {v184}='.227,1037–1050(2020).'` —— 两条路都堵
- 改判"整篇有没有中文": 英文原文回抄的确定特征是一处中文都没有。残留的
  "部分单元原样回抄"内容判据够不到, 由面板的**长度比读数**与人兜底(panel.py ③)
- 口径余量: 整篇 127 单元中文上限 70.9%(v31 时代同口径 97.8%) —— 门槛无论怎么拍,
  余量都被 v32 削掉一截, 这就是"过半"不再可用的根据

**用法**: `python watch_clip.py`(常驻) / `--once`(自检) / `--no-open`(不自动开 DOCX)

**教训**: 人工修正必须落回**源**(job_notes_response.tsv), 不能改派生物(notes_zh.json) ——
派生物会被对账器再生, 手改必丢。本次三处译名修正已按此归位。

## 9. 已实施件: panel.py(中继面板)用法

网页版(本机 127.0.0.1, 零依赖 stdlib http.server, 前端单页内嵌)。它把 watch_clip 的
"复制即执行"改成"**人看得见 + 人来提交**": 实测(2026-09-21)把真实回包的末行截掉 3 字符,
编号齐全 / 占位符未丢 / 非空, **G1-G5 全过**, 监听器直接出稿 —— 附录那一格就是错的。
这类缺陷判据够不到(锚点是编号与占位符, "末行被吃一截但还剩内容"两者都不触发), 唯一的
拦截点是把"提交"交回给人, 而且人得**看得见**末行是不是被截。

### 9.0 三段时序: 提字 → 面板 → 出稿(v28.79)

**前三段是硬顺序, 一步不落, 且出稿权只在第三段; 第四段是收场(自动)。** 动线:

| 段 | 谁做 | 做什么 | 费时/花钱 |
|---|---|---|---|
| ① **提字** | 插件(自动) | 只把原文切段、落 `inbox/<名>.txt` 载荷 —— **一次 LLM 都不调**, 所以秒级 | 秒级, 0 成本 |
| ② **面板到台前** | 插件(自动) | 载荷就绪 → **响铃** → 插件**自己**把中继面板拉起来并提到前台; 已有一份在跑就只提到前台 | 秒级 |
| ③ **确认出稿** | **人(在面板里)** | 粘贴豆包回包 → ③ 检查 → ④ 审核 → **⑤ 确认出稿**。不点 ⑤, 永不渲染 | 你说了算 |
| ④ **收场(可选)** | **人(在面板里)** | 概念链接区那颗**「完工, 关面板」**(v36.4)。**面板不再自己收摊** —— 加链接必须在成品出来之后做, 而旧版那条自动腿恰好在成品刚出来的那一刻开火 | 你说了算 |

**三段硬顺序, 收场交给人**: [v36.4] 出完稿面板**不会**自己收摊 —— 成品刚出来这一刻正是要加
概念链接的时候, 自动收摊会把这条动线掐在第一步。收场是你点概念链接区的**「完工, 关面板」**,
或直接关窗(见 9.4 腿②)。

**这一段以前是断的**, 也是本版堵的口:

- **铃响后面板根本不出现** —— 全仓库没有一行代码起 `panel.py`。现在服务端在响铃之后
  `_open_panel()`; 面板侧收到载荷就绪还会 `window.focus()` 自己往台前跳(两处都做, 是因为
  服务端拉起只保证"窗口在", 抢不抢得到焦点得页面自己来)。
- **插件会自己把回路走完** —— 提字后等豆包交件、回灌、重渲染**一气呵成**, 人还没看过就出稿了。
  现在提字后**收尾在「待译」**并就地退回, 剩下的全部等面板 ⑤。开关 `PAUSE_AUTO_ADOPT`
  缺省 `0`(= 不走自动回路); 设 `1` 才回到旧行为, 旧代码一字未删。
- **半路上的缓存是危险的** —— 提字那一趟按最终键形态落了一批 `translation == original_text`
  的**骨架行**, `seg_inject` 是 UPDATE-only, 正好改它们。回路要是停在中间、有人直接渲染,
  整篇命中骨架行 → **出来一份全英文 PDF**。故真要渲染的两条路(force / 关了两趟的机翻)
  开头都加了一道**护栏**: 台账显示"停在提字"就**拒绝渲染**, 并给两条出路(走 ⑤, 或
  `adopt.py rollback` 撤骨架行)。判据用 adopt 台账, 面板 ⑤ 跑完 inject 即**自动放行**。

**"叫面板"这一下要经得起细看(v28.79+)**: 服务端是用**分离进程**拉它的, 拿不到退出码、也读不到
那扇窗的输出 —— 于是"它起来了没""它到底在哪个端口"两问必须另有出处(面板自己报, 见 9.1
`--announce`)。据此, 进日志的那句话覆盖三种情况, 不撒谎:

- **起来了** → 报**它自己报上来的**端口(60642 被别人占着时面板会回落随机端口, 照旧报 60642
  就是把用户指到一扇没开着的门)。
- **没起来**(等了 4 秒没见它报端口, 多半是没 `P2Z_TABLE_DIR`/`P2Z_PROJ` 自己退了) → 明说没起来
  并给排查方向, **不写"已启动"**。
- **已经在跑**但不在 60642 上 → 只提到台前、**不起第二扇窗**(靠探一下回话文件里那个端口是否
  真有人应门; 陈年文件里留的端口不算数)。

另: 这套只在**要人点头**那条路上做。自动回路(`PAUSE_AUTO_ADOPT=1`)是无人值守的, 往人眼前弹窗
没有意义, 那条路不弹。

**③ 那一步为什么还是"人"**: 面板只给"看得见 + 人来提交", 门禁一律不降级 —— 正文走 adopt
回路且**不带 `--waive`**(见 9.6)。插件的自动回路本质是"把确认权也一起自动化了", 这版把它
拆开: 机器干机器的活(切段、对账、回灌、渲染), 确认归人。

### 9.1 启动

```powershell
$env:P2Z_TABLE_DIR="D:\zotero-pdf2zh-eval\logs\table_appendix"   # 数据(manifest/回包)在哪
& "$env:PDF2ZH_PYTHON" tools/table_pipe/panel.py    # 指向你的 venv python
```

- 固定端口 **60642**(记这个地址即可); 被上一个实例占着时**自动回落随机端口**, 实际地址看
  启动横幅第一行。窗口自动用 Edge/Chrome 的 `--app` 模式开(无浏览器框, 看着像原生弹窗)。
- 不弹窗(冒烟/自检): `$env:P2Z_PANEL_NO_OPEN="1"`。
- 无界面自检(跑门禁并打印待看清单): `python panel.py --selftest [回包文件]`。
- **服务端拉起时的回话**(不用手敲, 记个存在即可): `python panel.py --announce <文件>` —— 面板
  起来后把**自己实际的端口**写进那个文件。服务端是分离进程拉起它的, 拿不到退出码、读不到这扇窗
  的输出, 于是"起没起 / 到底在哪个端口"只能靠这个文件回答(见 9.3 铃响那一节)。写不成就只是少
  一条回话的线, 面板照常干活。
- **回收 60642**(旧实例占着、又想让它归位): `python panel.py --takeover` —— 走旧实例自己的
  告别腿请它退, **绝不代杀**(旧窗里可能压着未出稿的回包); 请不动就明说、回落随机端口。见 9.4。
- **起不来 / 退出码 2** = 工作目录与环境变量里没有任何任务的 manifest。提示会告诉你
  `P2Z_TABLE_DIR`(表格任务数据)与 `P2Z_PROJ`(正文任务的 inbox)该指向哪。
- 环境变量一览: `P2Z_TABLE_DIR` 表格数据目录 / `P2Z_PROJ` 项目根(正文) / `P2Z_INBOX` /
  `P2Z_BODY_NAME`·`P2Z_BODY_PDF`(手动指定正文任务, 不设则自动取 inbox 里最新的载荷) /
  `P2Z_REVIEW_DIR`(④ 审核报告落盘处, 缺省 `server/translated/review`)。

### 9.2 逐步操作(① → ⑤)

**编号按工序排**(v28.72 起重排过一次: 原来"④ 出稿 / ⑤ 报错明细 / ⑥ 语义审核"三个号与工序反着 ——
审核本该在出稿之前, 报错明细则根本不是一步操作)。现在: **④ 语义审核 → ⑤ 出稿**, 报错明细**不占号**
(它是 ③ 的输出物, 只在门禁 FAIL 时现身)。

| 步骤 | 动作 | 说明 |
|---|---|---|
| ① | **复制待译文本到剪贴板** | 把当前**任务**的装配件(`job_doubao.txt` / `job_notes_doubao.txt` / 正文 `inbox/<name>.txt`)整份写进剪贴板, 并报"几单元 / 几字符"。复制成功即往台账落一行(阶段「复制」= 外发历史, 见 9.3) |
| — | 粘进豆包网页版 | 面板管不着的一段, 人工 |
| ② | 把豆包回复**原样粘**进下方粘贴区 | 不挑不拣, 全文粘贴。**一改粘贴区, 之前的检查结论即作废**(横幅转为"内容已改") |
| ③ | **检查(只读预览)** | 在**临时目录**里跑同一份门禁代码, **不落任何文件**。产出: 顶部计数、**待看清单**(机器判不了的, 正常回包为**空**)、全表(编号/长度比/原文/译文)、门禁 FAIL 时自动出报错明细 |
| — | 报错明细(③ 的输出物, 自动出现) | 门禁 FAIL 时才有: 说到"哪段、缺哪个字形"、**责任归属**(豆包漏的 / 工装吃的), 可**复制给豆包**返工 |
| ④ | **语义审核**(手动, 付费) | 硅基流动 DeepSeek-V3.2 逐段核对「原文↔译文」, 报漏译/错译/数字/术语/指代/表达。**只审不改、不参与放行**; 结论可**复制给豆包**按"只改点到的段, 其余逐字符照抄"返工。**建议在 ⑤ 之前做** —— 出稿之后再审, 审出问题就要重做。**条目分两类去向**(v28.75): **译文侧存疑**才进返工单; **源文缺陷**(错的根在原文自己 —— 老扫描件的形近混淆 `011`=on / `340/00`=34‰、缺字、断字)只作**原文校勘**线索, **不进**返工单 —— 译者被规则要求逐字符照抄原文数字与字母, 要他改反而破坏字形回锚。**术语裁决可就地入表**(v28.76): 带「术语」的条目下方两格「原文术语 / 中文译名」+「存进术语表」, 一次写齐**两份格式不同**的表(1.x 的 `terms.csv`, 无表头可带注释、LF; BabelDOC 的 `terms.babeldoc.csv`, 带表头不能掺注释、CRLF) —— 手工维护必漏一份, 而漏掉的那份是**静默失效**(换引擎那个词不生效, 且无处报错)。审核者只报不改、不给候选译名, 两格由人裁决后填 |
| ⑤ | **确认写入并出稿** | 服务器先核对**内容指纹**(与 ③ 时一字不差才准写), 再落盘 + 排版 + 自动打开产物。写成功后清掉已检查状态(防双击重复出稿)。**会触发重渲染的任务(正文)另有保底底片, 以及"这一篇还有没出稿的"提醒**, 见 9.3 |

头部控件(左起): 标题 / 工作目录 / **表头「构建」时间** / **体检** / 切到浅色·深色。
**表头「构建」时间**(v28.79): 本面板吃的是哪一版代码 —— 取 `panel.py` / `watch_clip.py` /
`reviewer.py` 三份文件里**最新的** mtime, 显示成 `构建 09-23 20:15`。用途一眼: 60642 上
可能挂着一个**旧实例**(见 9.4), 表头时间比你这版代码旧时, 眼前这扇窗就是旧的。
(旧的**倒计时 / 暂停自动退出**两个控件随心跳兜底腿一起删了, 见 9.4。)
**体检**(v28.77)一键把实测踩过的静默陷阱变成红灯, 只读不动文件, 日志区一行一项如实报:
术语**双表漏同步**(v28.76 写入侧一次写齐两份, 体检是读取侧对账 —— 漏的那份静默失效)/
表里坏行与表头口径 / `config.toml` 的 **Ital 吞斜体**(整段被吞成"公式")/ **8890·60642
新旧实例共存**(SO_REUSEADDR 让"重启"变成新旧并存, 服务的还是旧的)/ **④·ledger 目录
不可写**(落报告与出稿会半路硬停)。红灯照说明处理, 黄灯只是提醒, 都不拦你干活。
"任务"行里还有: 任务下拉(**正文排最前**; 换论文后自动切到最新载荷)、**重新装配**
(表格任务跑 `mk_job.py`, 会清掉已检查状态)、以及下面的日志区。

**⑤ 出稿按钮下方还有一块「概念链接」区**(v28.73) —— **出稿之后**用它。原版超链接是继承来的
(引文锚 → 文献表, 学名 → 附录), 读者只能点原书给的那几条; 而"读到这里我需要一点背景"这种需求
原书不会替你想到, 位置该由读者定。动线: **从成品页上点选一行文字当锚 → 填网址 → 提交**。
提交前面板先跑一次 `user_links.py --check`(只预检、**不落盘**), 把"命中几处 / 该不该给第几处 /
压住了哪条原链接"摆出来; 确认后装入, **并自动接着跑 `style_links`** 把新锚染蓝 —— 不变蓝读者
就看不出能点, 所以这步顺序由代码保证, 不靠人记。面板**不重写任何判据**, 门禁全在
`tools/user_links.py` 里(口径与手写命令见 README「把你自己的概念链接装进去」); 规格落在仓库根的
`user_links.json`(`global` 跨篇 / `tasks.<篇名>` 本篇), 与手写共用同一份文件。

**装到哪儿 / 什么时候收场(v36.4)**: 装入有**两个去向**, 都由**后端自己**算(`/api/ulapply` 的
`mode`, 浏览器不能指路 —— 与"不许浏览器指哪儿改哪儿"同一道门):

| 按钮 | mode | 落点 |
|---|---|---|
| 装入成品并变蓝 | `inplace` | **就地**改探测到的那份成品 |
| 另存为一份带链接的 | `saveas` | 先 `copy2` 成 `<成品名去后缀>` **`.links.pdf`**(如 `…-mono.links.pdf`), 再改**副本** —— 原成品一个字节不动; 每次都从**干净成品**复制, 不在旧副本上叠 |

**没有"覆盖 Zotero 附件"这条去向**(2026-09-26 讨论后据证据否掉): 那等于在**别的程序正管着该
文件**的时候去改它 —— 可能被阅读器占住、可能正被同步, 而且失败是**静默的**。正确动线是**顺序**:
先把链接装进**我们自己的成品**, **再**把这一份交给 Zotero(拖进去 / ZotMoov 移进去) —— 于是
Zotero 拿到的天生就带链接, 谁都不必去改它管的文件。旁边那颗**「打开文件夹」**就是为这一步准备的。
收场点**「完工, 关面板」**: 面板**不会**自己关(见 9.4 腿②)。

**再往下是「结构自愈」区**(v28.78) —— 同样**出稿之后**用, 治的是"**文字没翻错、版面坏了**"
这一类结构伤(此前只能手敲 CLI, 用户够不着)。两件**成品级**工具挂成三个按钮:

| 按钮 | 背后工具 | 治什么 / 判据在哪 |
|---|---|---|
| 只看伤情(不落盘) | `heal_render.py --dry-run` | 干跑即体检: 有伤**未治**时退出码 1(是"查出伤", 不是失败), 一个字都不写 |
| 治版面伤 | `heal_render.py` | 旋转文本 / 文献区错位这类版面伤; 落盘后**重开核对** redact 前后链接数 |
| 治链接伤 | `relink_pages.py` | 链接热区按**锚文本重搜搬矩形**; 未命中的锚保持原矩形 —— 不死链 |

**透明是准入条件**(见 §9.6 红线): 两件都只动结构层(版面 / 链接热区), **不碰译文一个字**;
每次自愈都出报告, 落在**成品旁边**(`<成品名>.heal.自愈报告.txt` / `.relink.自愈报告.txt`,
审计轨迹跟着产物走, 隔天回看还在)。面板只做三件事: **组参数**(`--target` / `--original` /
`--report` 由面板补齐, dual 成品加 `--dual`, relink 拿得到侧车就传 `--sidecar`)/ **入口守卫**
(成品必须落在自动探测候选里 —— 会改 PDF 的工具, 不许浏览器指哪儿改哪儿, 与概念链接同一道门)/
**一字不改转述**(工具 stdout+stderr 与报告原文照搬, 不描补、不吞错)。

`dedouble_sweep`(要 cache 库 + fingerprint)与 `force_rerender`(引擎级重渲染, 要异步与进度)
**形态不同, 是第二期**, 不硬塞进同一个按钮 —— 一个按钮一件事, 别让"自愈"变成许愿池。

### 9.3 一篇论文收尾: 本篇待办 · 提醒 · 保底底片(v28.69→v28.71)

一篇论文往往既有正文又有表格。早先(v28.69)的判据是"**你复制过的**都做完了吗": ① 复制即把
该任务记进**内存清单**, ⑤ 出稿正文时清单里还缺就近**硬拦**, 外带一颗「仍然出稿」的逃生门。
v28.71 把这条线整个推翻, 两层理由:

- **清单记的是鼠标动作**: 重启面板就失忆, 也管不了"你压根没碰过的那块表格";
- **更要紧的是拦错了对象**: 查依赖, 渲染一路(`server/` `patches/` `engine.py` `seg_*`)从不读
  表格产物 —— `table_*.zh.tsv` / `notes_zh.json` 只有 `mk_appendix.py`(排附录)与
  `mk_ledger.py`(底片)在读, `P2Z_TABLE_DIR` 也只有表格工具自己用。**PDF 里的表格页本来就
  保持英文**, 表格译文走附录 DOCX 这条路。所以"表格没做完就渲染"不会让 PDF 出问题, 只意味着
  附录还没生成(随时可重做, 不是单程票)—— 拿它硬拦是自作主张。

**本篇待办**(操作区下方常驻一行) —— 列出**这一篇**该做的每一块及状态:

| 显示 | 状态 | 判据 |
|---|---|---|
| `✓ 已出稿` | `done` | 产物齐全, 且不比输入旧 |
| `⟳ 要重做` | `stale` | 产物比输入旧 = **装配过新一轮**(重跑过 `mk_job.py`) |
| `○ 未出稿` | `todo` | 产物缺 |

判据全部落在**产物**上(`watch_clip.released`), 不存内存 —— 重启面板、隔天回来都不失忆。

**篇归属** —— 表格/表注 manifest 里的篇名是**装配器烙的**: `mk_job.py --paper <篇名>`
(缺省取 env `P2Z_BODY_NAME`, 面板「重新装配」走的就是这条), `mk_notes_job.py` 沿用同目录
`job_manifest.json` 里那份(表注是手工跑的, 不另要参数)。与正文那篇一致 = 本篇的; 老目录
没烙(留空)则按"一个工作目录 = 一篇"当本篇的, 并标「(未标篇名, 按本篇算)」让人核; 烙了但
不一致的标「(另一篇的)」—— 仍列出来让你看得见, 但**不进提醒**(那是别人的表, 不该算你欠的)。

**提醒, 不拦** —— ⑤ 出稿**会触发重渲染**的任务(正文)时, 若这一篇还有没出稿的: 横幅转琥珀色、
日志两行说清"还差谁 / 为什么不要紧", 台账记成「已出稿(缺: <短名>)」, 然后**照旧渲染**。
顺序随你, 齐了就过, 缺了提醒。表格正文/表注的 ⑤ 只是排版, 不提醒、也不记「缺」。

**保底底片** —— 渲染**之前**, 把此刻已过的译稿固化成一份人读 Word: `<PDF 文件名>_译稿.docx`,
落在 `<项目根>\ledger\`(如 `D:\zotero-pdf2zh\ledger\`)。两节: 一、正文(逐段 原文灰 / 译文黑,
按 `#S` 升序); 二、表格与表注(真表格, 可翻格内上原文下译文; 无译文的格只留原文, **不编造**;
表注取自 `notes_zh.json`)。生成器 `mk_ledger.py` **只读**既有产物、不写工作目录。

**底片做不出来就直接报错、不出稿**(v28.70 起的口径): 放它渲染的后果是 PDF 照样出来、而且与
正常那份**一模一样**, 想补底片只能重走一遍出稿 —— 白多一份 PDF 等人去删。所以宁可当场停住。
报错会说明哪一步没成; 回包已经落盘, 你修好后**重新点 ⑤** 即可(不用重贴, 也不用重跑 ③)。
这是**硬拦**, 与上面那条"提醒不拦"不是一回事: 它拦的是"存档点没生成", 不是"你还欠几块"。

### 9.4 退出(两条腿) + 60642 旧实例接管(v28.79)

- **腿① 关窗即退**: 页面关窗前发 `/api/bye`, 进 `BYE_GRACE=15s` 宽限期; 期内有新心跳(F5 刷新、
  还有别的标签页活着)则告别作废 —— 所以刷新页面不会自杀。
- **腿② 完工关面板(v36.4)**: 概念链接区那颗**「完工, 关面板」** → 面板过 `CLOSE_GRACE=3` 秒
  自己关停(留这几秒是让"面板即将关停"那句回话先回到页面上)。**只有人按了才关**,
  这条动线上**没有任何自动收摊**。
  [v28.79~v36.3] 曾有过一条"⑤ 出稿成功且这一篇该做的都出齐了 → 自己关停", **已删**: 它开火的
  时刻恰恰是成品刚出来那一刻, 而概念链接**必须先有成品才能做** —— 等于把动线掐在第一步。
  `paper_done` 的判据留着, 但它现在只在出稿日志与响应(`done`)里说一句"这一篇齐了", 不驱动行为。
- **心跳兜底已删**: v28.60 曾加过一条"心跳静默 **30 分钟** = 窗口已关"的兜底自灭腿, 还配了
  头部倒计时与「暂停自动退出」。**整条删掉**: 这条动线上人要在面板里看回包、改稿、重贴,
  30 分钟是个"估出来的"时限, 只会把正常干活的人当死窗口处理。
  删掉之后"浏览器崩了、告别没送出去"会让面板常驻 —— [v36.4] 这条常驻**被接受**了: 收场改由人
  点「完工, 关面板」或关窗, 而常驻本身没代价(只占一个端口; 表头「构建」时间一眼认得出是不是旧实例)。
  真要把端口收回来, 走下面那条 `--takeover`(前提是旧实例还应答 HTTP)。
- `Ctrl+C` 也能停(在启动它的那个终端里)。**自动拉起的那扇窗不受 Ctrl+C 管**(分离进程) ——
  它的正常收场是人点**「完工, 关面板」**(腿②)或关窗(腿①); 半路夭折时若端口被占住, 见下面接管。
- **60642 旧实例: 只识别, 绝不代杀**(v28.79): 端口占着而你又起一份时, 新实例会探一下
  60642 上是不是**自家面板**(探 `/api/state` 有没有那几把自家钥匙)。是自家的就走它的
  **告别腿**请它自己退 —— 用 `--takeover`(`python panel.py --takeover`), 它会 POST 旧实例的
  `/api/bye`, 等它自己收工再接管端口。**为什么不 taskkill**: 旧窗里可能正压着**没出稿的回包**,
  一刀杀掉等于替用户丢了还没确认的活。请不动(或 60642 上根本不是自家面板)时新实例**明说**
  "60642 没腾出来", 回落随机端口, 实际地址看横幅 —— 不静默换端口, 也不假装成功。
  **注意它的前提**: 旧实例得还活着、还应答 HTTP —— 进程卡死时探不到自家钥匙, 接管也会失败,
  那就只能手工处理。**实见的一种更刁的形态**(2026-09-23): 探得到、`/api/bye` 也受理了(返回
  `{"ok": true}`)却一直不退 —— 看门狗线程已经不在干活, 告别就成了一句空话。认 PID:
  `Get-NetTCPConnection -LocalPort 60642 -State Listen` 看 OwningProcess, 再结束它;
  浏览器那扇窗杀掉之前先看一眼里面有没有还没出稿的回包(服务器停掉不会抹掉标签页内容,
  选中复制出来贴进新面板即可)。
- 顺带一眼认版本: 表头「构建」时间就是本面板吃的代码版本(见 9.2), 比你这版旧 = 眼前是旧实例。

### 9.5 出问题时

| 症状 | 先查什么 |
|---|---|
| 网页报"连不上本机服务器" | 八成是**旧页面**连着一个已退出的实例: 关掉那扇窗/标签, 重开 `http://127.0.0.1:60642/` |
| 拿不准环境有没有踩静默陷阱 | 先点头部**「体检」**(只读不动文件): 术语双表漏同步 / 表里坏行 / config Ital 吞斜体 / 8890·60642 新旧实例共存 / ④·ledger 目录不可写 —— 一行一项如实报, 红灯照说明处理后再点一次复查 |
| 60642 打不开, 但终端说起来了 | 端口被上一个实例占着 → 新实例回落了**随机端口**, 用横幅里那行的地址; 想回收 60642 就重启面板时加 `--takeover`(请旧实例自己退, 见 9.4, **不代杀**) |
| 想确认谁占着端口 | `Get-NetTCPConnection -LocalPort 60642 -State Listen` 看 OwningProcess, 再用 `Get-Process -Id <pid>` 核对 |
| "剪贴板被别的程序占住" | 稍后重试(剪贴板是全局独占资源) |
| ④ 报密钥/额度问题 | 密钥口径: 环境变量 `SILICON_API_KEY` / `SILICON_MODEL` / `SILICON_BASE_URL` 优先, 否则读 `server/config/config.json` 的 `translators[silicon].envs` |
| ③ 检查通过但 ⑤ 拒绝 | 粘贴区在 ③ 之后被改过(指纹对不上), 重新点 ③ 即可 |
| ③ 全绿, ⑤ 却报门禁没过 | 正文那一格 ③ 只跑得到**第一道门**(`seg_import`); ⑤ 出稿时还有**第二道门**(adopt `deliver`/`import`: ⋮ 断点对账 / 只译半截 / 逐段不变量)。两道判据不同, ③ 过**不等于**全过 —— ⑤ 会说是哪一道、缺在哪段, 修正后重贴或重跑即可(③ 结束时也会点这一句)。 |
| ⑤ 提示「这一篇还有没出稿的: …」 | 只是**提醒不是拦**: 那几块随时可补(见 9.3)。PDF 的表格页本来就保持英文, 只有附录还没生成/底片里那节是空的 —— 之后单独把表格做完即可, 顺序随你 |
| ⑤ 出稿后**面板自己关了** | [v36.4] **不会了** —— 面板不再自动收摊(原因见 9.4 腿②)。出完稿请接着去**概念链接**区: 把链接装进成品, 再把这一份交给 Zotero; 收场点那颗**「完工, 关面板」** |
| ⑤ 出稿后**面板没关** | [v36.4] 这是**正常**的: 面板只在人点「完工, 关面板」时才关。日志里琥珀色那句"还有没出稿的"只是提醒; 齐了也只是多一句"这一篇该做的都出齐了"(纯提示, 不会关) |
| 待办行显示「⟳ 要重做」 | 装配过新一轮(重跑过 `mk_job.py` / 换了 `--paper`), 旧产物比输入旧了: 那一块要重新走一遍 ③⑤ |
| ⑤ 报「底片没做成, 已拦下出稿」 | 这是**故意不渲染**(见 9.3): 存档点没生出来就不出稿, 免得事后多一份一样的 PDF 要删。按报错里的原因处理(`ledger\` 写不进去 / 没有可固化的译稿…), 修好后**重新点 ⑤**, 回包不用重贴 |
| 想手动补一份底片 | `python mk_ledger.py --paper "<论文名>"`(只读既有产物, 不动出稿流程) |

### 9.6 面板**不**做什么(防误用)

- **不翻译**: 翻译者始终是豆包(网页版), 面板只管装配 / 核对 / 落盘 / 排版 / 审阅。
- **不放宽门禁**: ③ 与 ⑤ 用的是同一份门禁, 面板只能在"过"之后帮你落盘, 不能让你跳过。
  **正文那一格的"确认"是"我确认出稿", 不是"我放行门禁"**(v28.79): 正文工序改走 adopt 回路
  (`deliver → import → inject → force_rerender`), 且 **不带 `--waive`** —— 断点对账 / 只译半截 /
  逐段不变量这几道内容门照跑, 过不去就是出不了稿。面板上**没有**"我知道有错, 但还是出稿"这颗按钮。
  (改走 adopt 也是补课: 老路 `seg_import` 单跑少这三道门, `seg_inject` 又没给 `--fp`、
  静默回落到别的文档指纹 → UPDATE 命中 0 行 → "报成功"而渲染还是英文。找不到 adopt 台账
  的老载荷才回落老路。)
- **不替你定顺序**: 表格、表注、正文谁先谁后都可以 —— 缺了只在出稿正文时提一句(见 9.3),
  不拦、也不给你一颗"强行跳过"的按钮。
- **不跳过底片**: 会触发重渲染的任务, 出稿前必留一份底片; 生不出来就不出稿(见 9.3)。
- **不改判据**: 门禁口径在 `check_job.py` / `seg_import.py`, 改判据要改代码与测试, 不是在
  面板上点一下。
- **④ 不产出改写稿**: 生成式改写不可信(见 `PIPELINE_STORY.md` 第七章"润色钩子小传"),
  它只列存疑, 改不改、怎么改由你裁决。
- **自愈只动结构层, 且必须透明**(v28.77 定的准入条件, **v28.78 起已生效**):
  不碰译文一个字 —— 只治"文字没翻错、版面坏了"的结构伤(判据全在工具里写死, 面板只转发
  与转述); 每次自愈都**出报告**(治了哪页、按哪条判据) —— 不透明的"顺手修"宁可不做。
  认知劳动(查词、裁决、积累)归用户, 结构劳动(格式、渲染、链接)归工具 —— 但归工具不等于
  "出了问题来找维护者", 得让用户**自己够得着**(体检 v28.77、自愈 v28.78)。

## 10. 换翻译方: 这条管线不绑豆包(v28.62)

**结论**: 剪贴板这条路从第一天起就是**厂商无关**的 —— `watch_clip.py` 开头那句"手工复制这
条路换任何 AI、任何版本都不会坏", 说的就是这件事。豆包是**默认**, 不是**依赖**。

真契约只有两条, 任何网页 AI 满足即可接:

| 契约 | 违反的后果 |
|---|---|
| **编号守恒**: 发出去的 `#S45` / `k001` 一条不少地回来 | ③ 当场挡住并列出**缺哪几条**(不是静默错译) |
| **占位符原位**: `{v29}`、`{S003}` 不丢、不挪、不改写 | 门禁的字形/占位符断言 FAIL |

载荷自带抬头(文档名、术语表、逐段规则), 所以**换家不用改提示词**。有没有 MCP 桥不受影响:
桥(`doubao_bridge.py`)只是豆包的便利通道, 没有桥的网页 AI 走 ①/② 的复制粘贴。

### 10.1 换一家要做的事: 只改一处

面板头部 **「翻译方」下拉**选一下即可(选择落在工作目录的 `.panel_vendor`, 重启面板仍在)。
选完自动跟上三件事:

- **归因** —— ③ 检查、⑤ 出稿各往 `vendor_ledger.tsv` 追加一行;
- **措辞** —— 报错明细的责任归属显示"翻译方的问题 · <你选的那家>";
- **守红线** —— ④ 的同源判断(见 10.3)。

### 10.2 别家的"包装"我们替你剥掉(watch_clip.parse_units)

豆包网页版习惯裸文本, 而别家常这样回, 三者都只动**包装、不碰译文一个字**:

| 形态 | 处理 |
|---|---|
| ``` / ```markdown 代码围栏(整篇被围) | 只丢**围栏行**, 围栏中间的内容照收 |
| 首尾客套("以下是译文" / "希望对你有所帮助") | 只丢**尾部**、且要求"起首即客套词 **且** ≤40 字 **且** 与译文隔空行" |
| 编号被列成清单(`- #S1`、`1. #S1`、`(1) #S1`)或加粗(`**#S1**`) | 编号行容忍这些行首包装, 正常认出来 |

**刻意不做**的两件(宁可漏洗不可误吃):

- **不剥内容行里的项目符号** —— 译文本身可能就是列表("- 根系分布受水分影响。"), 剥了就
  是在改译文;
- **首部客套不用管** —— 编号行之前没有"当前段", 那些行天然落不到任何一段上。

已知残留: 客套**紧贴**末段(中间没有空行)时不会洗, 会留在末段译文里 —— 那属于"人该看一眼"
的范畴(报错明细/全表看得到), 好过把末段真句子误删。

### 10.3 红线: 翻译方与审核者**不得同源**

`relay_spec` §4.5(被翻译方不得自校)在换家之后的落点: 若翻译方选了 DeepSeek 系
(DeepSeek 网页版 / 硅基流动 API), 而 ④ 审核者也正是 DeepSeek-V3.2 —— 那就成了自己给自己
打分, **④ 直接拒审**(服务器端拦, 拦在联网之前, 不花这笔钱; 前端同时禁用按钮, 那只是提示)。
判据是"按名字认族"(`reviewer.family_of`), 认不出的组合不拦, 但审核报告抬头会写明
"翻译方 / 审核者"两边是谁, 事后看得出是不是一家。

要换**审核者**本身: 改 `reviewer.py` 的 `SILICON_MODEL` / `SILICON_BASE_URL`(或同名环境
变量), 与翻译方错开族即可。

### 10.4 台账: "换家到底行不行"看这里

工作目录下的 **`vendor_ledger.tsv`**(追加式, 不参与门禁):

    时间	阶段	任务	翻译方	单元	待看	结论	备注

- 每次 ③ 检查一行(结论 过/未过, 待看 = 机器判不了、留给人核的条数);
- 每次 ⑤ 出稿一行(结论 已出稿/出稿失败);
- 回包连编号都不齐时也记一行(结论"编号不齐", 备注带一行诊断)—— 那正是"这家行不行"的证据。

**比一家的正确姿势**: 同一篇论文、**同一份载荷**(① 复制的东西不变), 两家各贴一轮, 比
③ 的门禁结论 + 待看条数 + ④ 的存疑条数。别拿不同论文比 —— 题目难度不同, 数字没有可比性。

### 10.5 现实约束

- **网页输入框长度上限**是唯一的硬约束: 载荷整篇贴得进去才行(表格任务按表切, 正文按段表切,
  已经切过一轮, 单份通常远小于常见上限);
- 若某家**拒绝整篇输出**或自作主张分段回, 门禁会以"编号不齐 + 缺哪几条"挡住, 不会静默出错;
- 换家**不影响**门禁口径与产物格式: 回包最终都被规范化成同一份 TSV / `#S` 文本, 下游
  (`check_job.py` / `seg_import.py` / 排版)分不出、也不需要知道是谁翻的。
