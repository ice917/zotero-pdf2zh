# 中继器(relay)规格 —— 表格翻译管线缺失的一环

状态: **本地侧已实施**(watch_clip.py, 见 §8); 远端侧仍冻结待触发 | 定稿: 2026-09-21
依据: 端到端演练已通(mock) + 真实往返已通(豆包网页版, 见 check_report.txt)

## 1. 定位

```
mk_grid.py(切格) → mk_job.py(装配) → 【中继: 本件】 → check_job.py(对账回填)
```
两端已实测跑通; 中继是唯一缺失件, 故意做薄(目标 ≤150 行)。

## 2. 接口契约(冻结)

- 输入: `job_doubao.txt`(编号<TAB>文本, ≤2k 字符/表, 一次粘贴量)
- 输出: `job_response.tsv`(编号<TAB>译文, 原样落盘, 后续由 check_job.py 验)
- 内部统一走 **OpenAI Chat Completions 格式**(messages = preamble + job 文本)
- **后端 = 可替换件**, 四选一, 接口不变:
  1. 人工粘贴(现状, 0 成本, 每表 2 次粘贴)
  2. 官方 API(最稳, 付费)
  3. 本地模型 Ollama(免费+全私有; 任务已剥到只剩自由文本短语, 小模型可能够用)
  4. 网页逆向网关(免费, 见 §5, ToS 灰色)

## 3. 触发条件(何时才造)

- 一本书 >5 张表, 或多本书批量化 —— 未触发前人工中继是最优解
- 豆包连接器/任务功能收费化 → 退回普通对话框, 管线不受影响(实测未依赖连接器)

## 4. 权限边界(红线, 写死)

1. 只读白名单目录(如 `logs\table_appendix\`), 无全盘权限
2. 无上传权 —— 只取 job 文本, 本地文件本体(PDF/manifest)永不离开
3. 只写 `job_response.tsv` 一个文件
4. 凭据(sessionid/API key)存本地配置, 不进 git
5. **校验权不外放** —— 对账永远本地跑, 被翻译方不得自校(G1-G5 门禁)

## 5. 调研结论(2026-09-21, 网搜)

**网页 AI 转 API(豆包无官方免费接口的替代):**
- `doubao2api` (github.com/wangchuxiaoji-oss/doubao2api): Playwright+Chromium **BrowserOnly** 架构, 浏览器内 fetch 由字节 JS 自动注入 a_bogus/msToken 签名("不逆向签名, 逆向浏览器环境"), 暴露 OpenAI 兼容 `/v1/chat/completions`; 扫码登录一次, 会话持久化; 不需会员
- `LLM-Red-Team/doubao-free-api` / `1994qrq/2025doubao-free-api`: sessionid cookie 逆向代理, OpenAI 格式互译(较老, 纯协议伪造, 有风控风险)
- ⚠ 风险: 逆向 = 服务条款灰色; 账号有风控/封禁可能; 后者 README 被自动扫描标出 secret-exfiltration 提示, **采用前必须通读源码**

**Zotero 生态(网页 AI 接入先例, 证明模式成立):**
- `zotero-pdf-translate`(windingwind, 11.8k★): 翻译服务里有 **Custom GPT** = 任意 OpenAI 兼容端点 → 本地跑 doubao2api 后 Zotero 可直接把它当翻译服务
- `llm-for-zotero`(yilewang): 支持 **WebChat 模式**(不用 API key, 驱动网页版 ChatGPT/DeepSeek) —— "驱动网页 AI"已有实现先例
- Zotero AI Bar: 插件列表直接支持 Doubao

**通用:**
- `browser-use`: 通用浏览器自动化框架, 可作中继的驱动层(比逐站写 userscript 稳)

## 6. 决策建议

1. **只自动化本地侧**(已实施, §8); 远端侧保持手工, 触发条件未到不造
2. 造时只造中继层, 两端不动
3. 后端优先序: 官方 API > 本地模型 > 逆向网关(仅前两者不可用且用户知情时)

### 6.1 为何"只自动化本地侧"(2026-09-21 修订)

原判断"现在不造"针对的是**浏览器自动化**。修订后的分界更精确:

- **浏览器自动化越深越脆弱** —— 豆包改一次 DOM, 插件即废
- **手工复制粘贴这条路换任何 AI、任何版本都不会坏**, 且天然兼容免费版(无连接器/工作任务)
- 而"回复 → 文件 → 对账 → 出稿"这段 **100% 在本地**, 完全可控

故: AI 侧 = 一次粘贴 + 一次复制(手工); 本地侧 = 全自动。这样既拿到零操作体验,
又不引入任何远端脆弱性。

## 7. 隐私不变量(任何后端不变)

走出本机的只有 job 文本: 无表格结构、无学名/命名人/引文(禁翻列未发出)、数字全为 {S###} 占位符、无文件路径。保真不靠翻译方自觉, 靠 check_job.py 门禁。

## 8. 已实施件: watch_clip.py(本地侧中继)

```
mk_job.py(装配) → [豆包网页版 · 普通对话框 · 手工粘贴] → watch_clip.py → check_job.py → mk_appendix.py
                                                          ↑ 用户唯一动作: 在回复上点「复制」
```

把"存成文件 + 跑脚本"两步合并成一次 Ctrl+C。零依赖(剪贴板走 ctypes 调 Win32 API,
不需 pyperclip); 支持两类任务(表格正文 k 编号 / 表注 n 编号), 自动判别走哪个对账器。

**三重识别(防误触发, 全部实测)**

| 判据 | 作用 |
|---|---|
| 单元编号齐全(115 个 k / 3 个 n) | 日常复制凑不齐这么多连续编号 |
| 不含装配前缀 `【待译】`/`【任务】` | **防把发出去的 job 文本当回包**(它编号同样齐全) |
| 过半单元含中日韩字符 | 防把英文原文当译文 |

**实测记录(2026-09-21)**

- 表格回包(把真实回包 TAB→空格模拟网页渲染): 识别 115 单元 → G1-G5 全过 → 出稿。
  落盘内容与原始回包**逐条一致、顺序一致、零值差异**(哈希差异仅行尾空白)
- 表注回包: 识别 3 单元 → G1/G2/G3/G5/G6 全过 → notes_zh.json → 出稿
- 防误触发: 剪贴板放入 job_doubao.txt 全文 → **无任何识别输出**, 正确忽略

**用法**: `python watch_clip.py`(常驻) / `--once`(自检) / `--no-open`(不自动开 DOCX)

**教训**: 人工修正必须落回**源**(job_notes_response.tsv), 不能改派生物(notes_zh.json) ——
派生物会被对账器再生, 手改必丢。本次三处译名修正已按此归位。
