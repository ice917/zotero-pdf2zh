# {vN} 占位符协议契约（pdf2zh 1.x 魔改栈）

> 本文档是跨层字符串协议的唯一权威描述。改动任何一层前必读。
> 维护原则: 协议变更必须同步更新本文档并跑 `tools/tests/run_all.py`。

## 1. 是什么

`{vN}` 是嵌入在"段落文本"字符串中的占位符，把不宜翻译的内容（公式、
被 vfont/vchar 判定的字符序列、(cid:NN) 解出的符号）从翻译流中摘出，
渲染时用原字体原内容回填。它贯穿三层：

```
converter 解析 ──→ 原文段落串(含{vN}) ──→ translator/缓存 ──→ 译文串(含{vN}) ──→ converter 渲染回填
     var[] 全局表                    cache.v1.db                       var[N] 原字体绘制
```

## 2. 生命周期与不变量

### 2.1 创建（converter.py 解析期）
- var 按**字符处理顺序**全局递增编号: `sstk[-1] += f"{{v{len(var)}}}"; var.append(vstk)`
- **不变量 I1**: 同一段落内，原文中 {vN} 的出现顺序严格递增（v23 规范化依赖此序）
- **不变量 I2**: var 内容与位置一一对应；段落文本与 var 表同生共死

### 2.2 翻译与缓存（translator.py / cache.py）
- 缓存键 = (engine, params_json, original_text)。v23 起 original_text 以
  **规范形态**入库: {vN} 按段内出现序重编为 {v0},{v1},…（`_canon_seq`）
- 命中时 `_remap` 把存入译文的重映射到当前全局编号；LLM 自造 token 原样保留
- **不变量 I3**: 缓存译文中的 token 必须能在存入原文中找到（自造 token 是
  已知垃圾，行为与 v22 前一致，不新增）
- **不变量 I4**: 术语表后缀(`#g23:`)与 prompt 注入必须使用同一套 `_norm` 匹配

### 2.3 渲染前整形（converter.py，翻译之后、排版之前）
顺序固定: ① v20 `_strip_punct_placeholders`（纯标点占位符消除）
② `_split_mixed_placeholders`（混合段首尾标点整形，**会追加新 var**）
③ 邻接重复标点收敛
- **不变量 I5**: split 追加的新 var 用当时 `len(var)` 续编，仅存在于渲染期——
  **绝不入缓存**（cache.set 发生在 translate() 内，先于整形）
- **不变量 I6**: v20 映射表只含 `,.;:()` 六种；dash 变体删除；U+2212 转 ——

### 2.4 渲染（排版期）
- 译文串中 {vN} → `var[N]` 原字体回填；**禁止**再引入新 token 语法（如 {wN}，
  v23 设计期已评估并否决——cleaning lookbehind `}`、post_check、正则族全绑 {vN}）

## 3. 隐形通道（已知耦合，改动需两端同步）

| 通道 | 从 → 到 | 用途 | 约束 |
|---|---|---|---|
| `_tls.formula_map` | converter → translator | 报告可读化 ⟨公式:…⟩ | 仅展示用，逻辑不得依赖 |
| `sstk` 段落栈 | converter 内部 | 段落组装 | 补丁闭包直接读局部 var，上游重构即碎 |
| `polish_*` 参数族 | translator init → 缓存键 | 质量参数进键 | 文件指纹变更=旧键全失效(术语表已按段化, 指南未) |
| `~/.cache/pdf2zh/segflow/latest.jsonl`（+ v28.9 起每篇另落 `pdf-<原文内容md5[:16]>.jsonl`） | converter → `tools/adopt.py` · 军师层（本地工具，未随仓库开源） | 军师层段序流水(逐页 raw/trans, 首页截断)；归档件按**内容**认篇, 换/改名不覆盖, 供采纳管线 `--pdf` 认领 | 行内序号是**渲染时 current 序号**(可乱序/非 0 起), 不是库内 canon 序号; 写回缓存前必须经 raw 的 `_canon_seq` 重排(v24b.1), 否则占位符整体错位。每行另带 `vars` = 该页 `{vN}`→真实字形图例(v24b.2, 取自页内局部表 `var[]`, **同号跨页含义可不同**, 故图例随页携带不可全局合并) 与 `doc_fp`(v28.23, 文档画像指纹, 取自引擎缓存参数; 暂停档下 `adopt export` 靠它认领本篇 —— 库行是"翻过的产物", 骨架档没有产物, 从库行反推必然 0 命中)。`latest.jsonl` 仍是单文档假设: 并发多文档会互相追加到同一文件(归档件不受影响) |

## 4. 改动守则

1. **只动渲染/清洗层**（不改段落文本结构）→ 缓存键不变，无需重译；跑回归即可
2. **动 var 创建逻辑**（vfont/vchar/解析）→ 段落文本变 → 仅受影响段落 miss
   （v23 保证平移不级联）；用灵敏度脚本量化后入改动记录
3. **动缓存键语义** → 必须走"新形态直查 + 旧形态回查"双轨，禁止一次性作废旧条目
4. **动术语表** → 只影响含该术语的段落（v23 按段指纹）；指南/模型变更仍全量失效
5. 每次改动: venv 与 patches/ 双写 + `tools/tests/run_all.py` 全绿 + 改动记录.md

## 5. 已知边界（有意不修，勿"顺手修"）

- 句中句点孤儿("继承自[1]，的")：局部规则无法无歧义判定
- 半角 "((cP，c2))" LLM 自笔误：收敛会误伤真实嵌套括号
- 斜体标题 2 个 + arXiv 页脚不译：ReguItal 标题走特殊路径，收益/风险比不划算
